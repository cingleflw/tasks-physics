# Физический тест с конструктором наборов задач

Тест с конструктором (клиент-серверное приложение). Ученик выбирает одну или несколько тем по физике за 6–8 класс, а программа составляет для него набор задач со случайными числами: условие каждый раз новое, правильный ответ вычисляется автоматически.

**Прогресс:** выполнено 5 из 6 пунктов · 10 тем · 62 рандомизированные задачи

## Запуск

Задачи создаёт и проверяет собственный сервер `server.js`, поэтому сначала нужно запустить его. Нужен [Node.js](https://nodejs.org) версии 20 или новее; устанавливать пакеты не требуется — сервер использует только встроенные модули Node.js.

**Терминал:**

```bash
cd tasks-physics
node server.js
```

Затем откройте в браузере http://localhost:8000. Остановить сервер — Ctrl+C.

**WebStorm.** Нажмите правой кнопкой мыши на `server.js` → *Run 'server.js'* и откройте http://localhost:8000. Остановить сервер — красная кнопка *Stop* в окне *Run*. Значок браузера в правом верхнем углу редактора здесь не подходит: он открывает страницу со встроенного сервера WebStorm (`localhost:63342`), который не умеет создавать и проверять задачи. По той же причине не подходят `python3 -m http.server` и открытие `index.html` двойным кликом (адрес вида `file://...`) — вместо списка тем страница сообщит, что нет связи с сервером.

Отметьте одну или несколько тем, введите количество задач и нажмите «Начать тест». Пока нет интерфейса тестирования (п. 6), задачи по очереди показываются в окнах ввода — над условием написаны тема и номер задачи: введите ответ числом, сервер проверит его и сообщит результат. «Отмена» прерывает тест.

Новые темы и задачи добавляются в конструкторе: ссылка «Конструктор: добавить тему или задачу» внизу главной страницы или адрес http://localhost:8000/constructor.html (см. «Конструктор»).

Если что-то пошло не так:
- при запуске `Error: listen EADDRINUSE` — порт 8000 занят: уже запущен другой `node server.js` (например, в WebStorm) или ещё работает `python3 -m http.server 8000`; остановите его;
- появляется «Не удалось загрузить тему … (код ответа 404)» — браузер взял старый `main.js` из кэша (например, после запуска через Python); обновите страницу с очисткой кэша: Ctrl+F5, на Mac — Cmd+Shift+R (в Safari — Cmd+Option+R);
- «Задача не найдена» — сервер перезапускали: выданные задачи хранятся в его памяти, поэтому тест прерывается; начните его заново.

## Структура проекта

```
tasks-physics/
├── index.html        — страница теста: выбор тем и количества задач
├── main.js           — интерфейс теста: список тем с галочками, ввод ответов
├── constructor.html  — страница конструктора: формы темы и задачи
├── constructor.js    — интерфейс конструктора: разбор форм, предпросмотр, сохранение
├── api.js            — запросы к серверу (общий для обеих страниц)
├── server.js         — сервер: раздаёт страницы, создаёт задачи, проверяет ответы, сохраняет темы и задачи
├── generator.js      — система рандомизации: создание задачи по шаблону (подключается сервером)
├── validator.js      — проверка тем и шаблонов из конструктора (подключается сервером)
└── tasks/            — база задач, один JSON-файл на тему (читает и записывает только сервер)
    ├── 6_velich.json
    ├── 6_massa.json
    ├── ...
    └── 8_electric_current.json
```

Имя файла темы без `.json` — это её номер `id`. Список тем на главной странице сервер составляет по файлам папки `tasks/`: по классу, внутри класса — по алфавиту названий. Темы, в которых ещё нет задач, ученику не показываются.

## Формат задачи

Файл темы содержит её номер, класс, название и список шаблонов задач:

```json
{
    "id": "7_mechanics",
    "grade": 7,
    "title": "Механическое движение",
    "tasks": [
        {
            "id": 3,
            "text": "Поезд, двигаясь равномерно, прошёл {s} км за {t} ч. Найдите скорость поезда.",
            "params": {
                "v": { "min": 40, "max": 120, "step": 10 },
                "t": { "min": 2, "max": 6 }
            },
            "derived": {
                "s": "v * t"
            },
            "answer": "v",
            "unit": "км/ч"
        }
    ]
}
```

| Поле | Обязательное | Описание |
|---|---|---|
| `id` | да | Номер шаблона внутри темы |
| `text` | да | Текст условия. `{имя}` заменяется значением величины, `{имя.поле}` — полем выбранного варианта |
| `params` | да | Случайные параметры: `{ "min": 1, "max": 5, "step": 0.5 }` (шаг по умолчанию 1) или `{ "choices": [ ... ] }` |
| `derived` | нет | Вычисляемые величины в виде `"имя": "формула"`; считаются по порядку и могут использовать предыдущие |
| `answer` | да | Формула правильного ответа |
| `unit` | да | Единица измерения ответа |
| `precision` | нет | Количество знаков после запятой в ответе (по умолчанию 2) |

В формулах можно использовать числа, имена величин, знаки `+ - * /` и скобки. Варианты из `choices` могут быть объектами — так вещество выбирается вместе со своими свойствами:

```json
"params": {
    "material": { "choices": [
        { "name": "меди", "ro": 8.9 },
        { "name": "алюминия", "ro": 2.7 }
    ] },
    "V": { "min": 5, "max": 50, "step": 5 }
},
"derived": {
    "m": "material.ro * V"
},
"text": "Деталь из {material.name} имеет массу {m} г. Плотность {material.name} равна {material.ro} г/см³. Найдите объём детали."
```

Из шаблона получается задача, которая хранит свои случайные параметры:

```js
{
    topicId: "7_mechanics",
    taskId: 3,
    params: { v: 110, t: 2 },   // сохранённые случайные значения
    text: "Поезд, двигаясь равномерно, прошёл 220 км за 2 ч. Найдите скорость поезда.",
    answer: 110,
    unit: "км/ч"
}
```

Из этого объекта сервер сохраняет у себя только `topicId`, `taskId` и `params`, а браузер получает случайный номер задачи `id`, название темы, текст и единицу измерения (см. «Проверка ответов»).

**Правила составления задач:**
- ответ при заданной точности `precision` должен получаться точным, иначе в условии пишется «Ответ округлите до десятых»;
- все нужные константы (плотность, удельная теплоёмкость, g = 10 Н/кг) приводятся в условии;
- единицы измерения пишутся сокращённо («ч», «мин», «кг»), чтобы текст не зависел от склонения числительных.

## Выбор задач

На главной странице ученик отмечает галочками одну или несколько тем и вводит количество задач — от 1 до 100. Набор задач составляет сервер (функция `pickTemplates` в `server.js`). Шаблоны раздаются, как карты: у каждой выбранной темы своя колода — её шаблоны в случайном порядке. За один ход каждая тема, в колоде которой ещё есть шаблоны, отдаёт по одному шаблону, а очередь тем на каждом ходу случайная. Поэтому:
- задачи делятся между темами поровну: 3 темы и 4 задачи — по задаче из каждой темы и ещё одна из случайной темы. Если задач меньше, чем тем, их получают случайные темы;
- если в теме кончились шаблоны, задачи дальше дают остальные темы: тема из 2 шаблонов и тема из 8, 10 задач — все 10 шаблонов по одному разу;
- шаблон повторяется, только если задач больше, чем шаблонов во всех выбранных темах: тогда колоды тасуются заново. Например, 30 задач по теме из 6 шаблонов — каждый шаблон 5 раз;
- у повторённого шаблона сервер подбирает другие числа, чтобы условия в тесте не совпадали. Попыток не больше 10: у некоторых шаблонов всего около 10 разных условий, поэтому в очень длинном тесте одинаковые задачи всё же возможны;
- готовый набор перемешивается: задачи разных тем идут вперемешку.

## Проверка ответов

Задачи создаёт и проверяет сервер, поэтому подсмотреть правильный ответ в браузере (F12) нельзя. Для решения задач страница отправляет серверу запросы двух видов (а список тем получает запросом `GET /api/topics`, см. «Конструктор»).

**`POST /api/tasks`** — создать набор задач по выбранным темам (см. «Выбор задач»). Запрос `{ "topicIds": ["7_mechanics", "8_Om"], "count": 2 }`, ответ:

```json
{
    "tasks": [
        { "id": "b5f1…", "topicTitle": "Механическое движение", "text": "Поезд, двигаясь равномерно, прошёл 220 км за 2 ч. Найдите скорость поезда.", "unit": "км/ч" },
        { "id": "0c9e…", "topicTitle": "Закон Ома для участка цепи", "text": "…", "unit": "А" }
    ]
}
```

Повторы в `topicIds` не учитываются. Если список тем пуст — ошибка 400; если какой-то темы нет или в ней нет задач — 404, и ни одна задача не создаётся.

Сервер запоминает у себя `topicId`, `taskId` и `params` каждой задачи под случайным номером `id`. Даже `params` отправлять в браузер нельзя: в «обратных» задачах ответ — это один из параметров (в примере выше — скорость `v`).

**`POST /api/check`** — проверить ответ. Запрос `{ "id": "b5f1…", "answer": "110" }`, ответ `{ "correct": true, "correctAnswer": "110" }`.

Сервер находит задачу по `id`, заново вычисляет ответ по сохранённым `params` функциями из `generator.js` и сравнивает:
- ответ можно писать с запятой или точкой и с пробелами между разрядами: «2,5», «2.5», «42 000»;
- **допуск на округление** — половина единицы последнего знака, заданного `precision`, от точного (неокруглённого) значения. При `precision`, равном 1, допуск 0,05: если точный ответ 4,35, верными считаются и 4,3, и 4,4 (и сам 4,35), а при точном ответе 2,5 ответы 2,4 и 2,6 уже неверны;
- если ответ не число (например, «110 км/ч»), сервер просит ввести число, и попытка не тратится;
- на каждую задачу — одна попытка: после проверки задача удаляется, поэтому правильный ответ (`correctAnswer`) сообщается сразу.

Ошибки сервер возвращает в виде `{ "error": "текст ошибки" }` с кодом 400 (неверный запрос), 404 (тема или задача не найдена) или 500 (ошибка на сервере).

## Конструктор

Страница http://localhost:8000/constructor.html добавляет новые темы и задачи без ручной правки JSON. Вся проверка — на сервере (`validator.js`), а шаблоны задач базы конструктор не получает и не показывает.

**Новая тема.** Выберите класс, введите название и имя файла — номер класса, знак `_` и латинское название, например `7_pressure`. Сервер создаёт файл `tasks/7_pressure.json` без задач. На главной странице тема появится, когда в ней будет хотя бы одна задача.

**Новая задача.** Выберите тему и заполните поля — они соответствуют полям шаблона (см. «Формат задачи»):
- **текст условия** с подстановками `{p}` и `{material.name}`;
- **случайные параметры** — по строке на параметр: имя и вид. Диапазон чисел — «от», «до» и шаг (пустой шаг — 1). Список вариантов — по одному в строке: число (`0,5`) или набор полей `name: меди; ro: 8,9` (поле — число, если записано числом, иначе текст; в тексте поля не должно быть `:` и `;`, а числа пишутся без единиц измерения). Незаполненная строка параметра не учитывается;
- **вычисляемые величины** — по одной в строке: `F = p * S`;
- **формула ответа**, **единица измерения** и **знаков после запятой** (по умолчанию 2).

Числа можно писать с запятой или точкой (в формулах тоже: `m * 9,8`), имена величин — латинскими буквами, цифрами и `_`, начиная с буквы.

**Предпросмотр** показывает до трёх разных примеров задач с ответами и шаблон, который будет сохранён, если форму больше не менять (номер `id` сервер добавит при сохранении). **Сохранить задачу** дописывает шаблон в файл темы со следующим номером `id`; сервер подхватывает его сразу, без перезапуска. Оформление файла сохраняется таким же, как у файлов базы (описание параметра — в одну строку), поэтому в `git diff` видна только новая задача.

Перед предпросмотром и перед сохранением сервер проверяет шаблон и пробно создаёт по нему 1000 задач:
- **ошибки** — шаблон не сохраняется: незаполненные поля, имя не латинскими буквами или повторяется, «от» больше «до», шаг не больше нуля, в формуле есть что-то кроме чисел, имён величин, `+ - * /` и скобок или число начинается с нуля (`010`), у фигурной скобки в тексте нет пары, в тексте или формуле неизвестная величина, деление на ноль, а также параметр, который влияет на ответ, но не виден в тексте (его забыли подставить: одно и то же условие получается с разными ответами). Ограничен и размер шаблона: текст — до 1000 знаков и 20 подстановок, до 10 параметров и 10 вычисляемых величин, формула — до 200 знаков, до 50 вариантов у параметра (по каждому шаблону сервер создаёт 1000 пробных задач, и слишком большой шаблон надолго занял бы его);
- **предупреждения** — сохранить можно, но стоит проверить: ответ приходится округлять, а в условии об этом не сказано (см. «Правила составления задач»), все задачи получаются одинаковыми, в условии длинная дробь вроде 0,3333333333.

Проверка случайная: если неудачное сочетание чисел (например, деление на ноль) встречается очень редко, 1000 пробных задач могут его не заметить. Поэтому диапазоны стоит подбирать так, чтобы таких сочетаний не было вовсе.

**Ограничения:**
- пароля нет: добавлять темы и задачи может любой, кто открыл сайт (ответы задач базы при этом не видны);
- изменить или удалить тему или задачу в конструкторе нельзя — правьте файл в `tasks/` вручную, сервер перечитывает файлы при каждом запросе. При следующем сохранении задачи в эту тему файл будет записан в стандартном оформлении.

Для конструктора и списка тем сервер принимает ещё четыре запроса (ошибки — так же, как в «Проверке ответов»):
- **`GET /api/topics`** — список тем: `{ "topics": [ { "id": "8_Om", "grade": 8, "title": "Закон Ома для участка цепи", "count": 8 }, ... ] }`. Этот же список строит главную страницу; кроме номера, класса, названия и количества задач, ничего о задачах в нём нет;
- **`POST /api/topics`** — создать тему: `{ "id": "7_pressure", "grade": 7, "title": "Давление" }` → `{ "id": "7_pressure", "grade": 7, "title": "Давление", "count": 0 }`;
- **`POST /api/preview`** — предпросмотр: `{ "task": { "text": "…", "params": { … }, "derived": { … }, "answer": "p", "unit": "Па" } }` → `{ "template": { … }, "examples": [ { "text": "…", "answer": "600" }, … ], "warnings": [ … ] }`;
- **`POST /api/templates`** — сохранить шаблон: `{ "topicId": "7_pressure", "task": { … } }` → `{ "id": 1, "count": 1 }` (номер нового шаблона и сколько шаблонов стало в теме).

Все POST-запросы (и `/api/tasks`, `/api/check`) сервер принимает только с заголовком `Content-Type: application/json`, его ставит `api.js`, а тело запроса — не больше 100 000 знаков. Запрос с таким заголовком с чужого сайта браузер без разрешения сервера не отправит, поэтому обычная посторонняя страница, открытая в том же браузере, не сможет незаметно добавить задачи. От целенаправленных атак (например, подмены адреса через DNS) это не защищает — для учебного сервера на своём компьютере такой защиты достаточно.
