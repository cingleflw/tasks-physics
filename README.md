# Физический тест с конструктором наборов задач

Тест с конструктором (клиент-серверное приложение). Ученик выбирает тему по физике за 6–8 класс, а программа генерирует для него задачи со случайными числами: условие каждый раз новое, правильный ответ вычисляется автоматически.

**Прогресс:** выполнено 3 из 6 пунктов · 10 тем · 62 рандомизированные задачи

## Запуск

Задачи создаёт и проверяет собственный сервер `server.js`, поэтому сначала нужно запустить его. Нужен [Node.js](https://nodejs.org) версии 20 или новее; устанавливать пакеты не требуется — сервер использует только встроенные модули Node.js.

**Терминал:**

```bash
cd tasks-physics
node server.js
```

Затем откройте в браузере http://localhost:8000. Остановить сервер — Ctrl+C.

**WebStorm.** Нажмите правой кнопкой мыши на `server.js` → *Run 'server.js'* и откройте http://localhost:8000. Остановить сервер — красная кнопка *Stop* в окне *Run*. Значок браузера в правом верхнем углу редактора здесь не подходит: он открывает страницу со встроенного сервера WebStorm (`localhost:63342`), который не умеет создавать и проверять задачи. По той же причине не подходят `python3 -m http.server` и открытие `index.html` двойным кликом (адрес вида `file://...`) — при выборе темы страница сообщит, что нет связи с сервером.

Выберите тему и введите количество задач. Пока нет интерфейса тестирования (п. 6), задачи по очереди показываются в окнах ввода: введите ответ числом, сервер проверит его и сообщит результат. «Отмена» прерывает тест.

Если что-то пошло не так:
- при запуске `Error: listen EADDRINUSE` — порт 8000 занят: уже запущен другой `node server.js` (например, в WebStorm) или ещё работает `python3 -m http.server 8000`; остановите его;
- появляется «Не удалось загрузить тему … (код ответа 404)» — браузер взял старый `main.js` из кэша (например, после запуска через Python); обновите страницу с очисткой кэша: Ctrl+F5, на Mac — Cmd+Shift+R (в Safari — Cmd+Option+R);
- «Задача не найдена» — сервер перезапускали: выданные задачи хранятся в его памяти, поэтому тест прерывается; начните его заново.

## Структура проекта

```
tasks-physics/
├── index.html      — страница с кнопками тем
├── main.js         — интерфейс: выбор темы, запросы к серверу, ввод ответов
├── server.js       — сервер: раздаёт страницу, создаёт задачи, проверяет ответы
├── generator.js    — система рандомизации: создание задачи по шаблону (подключается сервером)
└── tasks/          — база задач, один JSON-файл на тему (читает только сервер)
    ├── 6_velich.json
    ├── 6_massa.json
    ├── ...
    └── 8_electric_current.json
```

Имя файла темы совпадает с атрибутом `data-topic` её кнопки в `index.html`.

## Формат задачи

Файл темы содержит её номер, класс, название и список шаблонов задач:

```json
{
    "id": "7_mechanics",
    "grade": 7,
    "title": "Механическое движение",
    "tasks": [
        {
            "id": 3,
            "text": "Поезд, двигаясь равномерно, прошёл {s} км за {t} ч. Найдите скорость поезда.",
            "params": {
                "v": { "min": 40, "max": 120, "step": 10 },
                "t": { "min": 2, "max": 6 }
            },
            "derived": {
                "s": "v * t"
            },
            "answer": "v",
            "unit": "км/ч"
        }
    ]
}
```

| Поле | Обязательное | Описание |
|---|---|---|
| `id` | да | Номер шаблона внутри темы |
| `text` | да | Текст условия. `{имя}` заменяется значением величины, `{имя.поле}` — полем выбранного варианта |
| `params` | да | Случайные параметры: `{ "min": 1, "max": 5, "step": 0.5 }` (шаг по умолчанию 1) или `{ "choices": [ ... ] }` |
| `derived` | нет | Вычисляемые величины в виде `"имя": "формула"`; считаются по порядку и могут использовать предыдущие |
| `answer` | да | Формула правильного ответа |
| `unit` | да | Единица измерения ответа |
| `precision` | нет | Количество знаков после запятой в ответе (по умолчанию 2) |

В формулах можно использовать числа, имена величин, знаки `+ - * /` и скобки. Варианты из `choices` могут быть объектами — так вещество выбирается вместе со своими свойствами:

```json
"params": {
    "material": { "choices": [
        { "name": "меди", "ro": 8.9 },
        { "name": "алюминия", "ro": 2.7 }
    ] },
    "V": { "min": 5, "max": 50, "step": 5 }
},
"derived": {
    "m": "material.ro * V"
},
"text": "Деталь из {material.name} имеет массу {m} г. Плотность {material.name} равна {material.ro} г/см³. Найдите объём детали."
```

Из шаблона получается задача, которая хранит свои случайные параметры:

```js
{
    topicId: "7_mechanics",
    taskId: 3,
    params: { v: 110, t: 2 },   // сохранённые случайные значения
    text: "Поезд, двигаясь равномерно, прошёл 220 км за 2 ч. Найдите скорость поезда.",
    answer: 110,
    unit: "км/ч"
}
```

Из этого объекта сервер сохраняет у себя только `topicId`, `taskId` и `params`, а браузер получает случайный номер задачи `id`, текст и единицу измерения (см. «Проверка ответов»).

**Правила составления задач:**
- ответ при заданной точности `precision` должен получаться точным, иначе в условии пишется «Ответ округлите до десятых»;
- все нужные константы (плотность, удельная теплоёмкость, g = 10 Н/кг) приводятся в условии;
- единицы измерения пишутся сокращённо («ч», «мин», «кг»), чтобы текст не зависел от склонения числительных.

## Проверка ответов

Задачи создаёт и проверяет сервер, поэтому подсмотреть правильный ответ в браузере (F12) нельзя. Страница отправляет серверу запросы двух видов.

**`POST /api/tasks`** — создать задачи по теме. Запрос `{ "topicId": "7_mechanics", "count": 2 }`, ответ:

```json
{
    "title": "Механическое движение",
    "tasks": [
        { "id": "b5f1…", "text": "Поезд, двигаясь равномерно, прошёл 220 км за 2 ч. Найдите скорость поезда.", "unit": "км/ч" },
        { "id": "0c9e…", "text": "…", "unit": "км" }
    ]
}
```

Сервер запоминает у себя `topicId`, `taskId` и `params` каждой задачи под случайным номером `id`. Даже `params` отправлять в браузер нельзя: в «обратных» задачах ответ — это один из параметров (в примере выше — скорость `v`).

**`POST /api/check`** — проверить ответ. Запрос `{ "id": "b5f1…", "answer": "110" }`, ответ `{ "correct": true, "correctAnswer": "110" }`.

Сервер находит задачу по `id`, заново вычисляет ответ по сохранённым `params` функциями из `generator.js` и сравнивает:
- ответ можно писать с запятой или точкой и с пробелами между разрядами: «2,5», «2.5», «42 000»;
- **допуск на округление** — половина единицы последнего знака, заданного `precision`, от точного (неокруглённого) значения. При `precision`, равном 1, допуск 0,05: если точный ответ 4,35, верными считаются и 4,3, и 4,4 (и сам 4,35), а при точном ответе 2,5 ответы 2,4 и 2,6 уже неверны;
- если ответ не число (например, «110 км/ч»), сервер просит ввести число, и попытка не тратится;
- на каждую задачу — одна попытка: после проверки задача удаляется, поэтому правильный ответ (`correctAnswer`) сообщается сразу.

Ошибки сервер возвращает в виде `{ "error": "текст ошибки" }` с кодом 400 (неверный запрос), 404 (тема или задача не найдена) или 500 (ошибка на сервере).
